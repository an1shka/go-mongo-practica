# Mini Chat на Go

Практическая работа: чат с регистрацией, входом, MongoDB, JWT и WebSocket.
Небольшой веб-интерфейс включён в Go-приложение и собирается внутрь исполняемого файла.

## Что умеет приложение

- Регистрация с проверкой имени и bcrypt-хешированием пароля.
- Защита от повторяющихся имён: предварительная проверка и уникальный индекс MongoDB.
- Вход с проверкой bcrypt-хеша и выдачей JWT сроком на 12 часов.
- Закрытый маршрут истории сообщений: `GET /api/messages`.
- WebSocket-подключение с проверкой JWT до обновления соединения.
- Сохранение сообщений в `chat_app.messages` и рассылка всем подключённым клиентам.
- Переподключение браузерного клиента после разрыва связи.
- Ограничение сообщения в 2000 символов и защита от слишком больших HTTP-запросов.

## Структура

| Файл | За что отвечает |
| --- | --- |
| `main.go` | Читает настройки, подключается к MongoDB, регистрирует маршруты и запускает HTTP-сервер. |
| `models.go` | Структуры пользователя, сообщения и форматы запросов/ответов. Пароль исключён из JSON. |
| `auth.go` | Проверка имени и пароля, создание и проверка JWT. |
| `handlers.go` | Регистрация, вход, проверка подключения к БД и чтение истории. |
| `websocket.go` | JWT-проверка, приём, сохранение и рассылка WebSocket-сообщений. |
| `hub.go` | Список активных подключений, безопасная рассылка и отключение медленных клиентов. |
| `auth_test.go` | Локальные проверки правил имени/пароля/сообщения и срока действия JWT. |
| `web/` | Веб-интерфейс: форма входа/регистрации и чат. |

## Настройки

Нужен Go 1.25+ и доступный MongoDB. Приложение использует базу `chat_app` и
коллекции `users` и `messages`. Если `MONGODB_URI` не задан, используется
`mongodb://localhost:27017`, как в исходной заготовке урока.

Перед запуском задайте переменные окружения:

```sh
export MONGODB_URI="mongodb://localhost:27017"
export JWT_SECRET="задайте-длинный-случайный-секрет-не-короче-32-байт"
export PORT=8080
```

В Replit вместо `JWT_SECRET` можно использовать уже настроенный `SESSION_SECRET`.
Не добавляйте `.env` с настоящими секретами в Git.

```sh
go mod tidy
go run .
```

Если MongoDB недоступна при старте, сервер всё равно запустит страницу и
покажет явную ошибку в журнале; запросы API вернут `503`. Когда база станет
доступна, сервер повторно подключится при следующих запросах и создаст нужные
индексы.

## API

### Регистрация

`POST /register`

```json
{"username":"arman_01","password":"strong-password"}
```

Имя пользователя: 3–32 буквы, цифры, точки, дефисы или подчёркивания.
Пароль при регистрации: 8–72 байта.

### Вход

`POST /login`

```json
{"username":"arman_01","password":"strong-password"}
```

Успешный ответ содержит `token` и `username`.

### История

`GET /messages`

Заголовок: `Authorization: Bearer <token>`.
Возвращает до 100 последних сообщений в хронологическом порядке.

### WebSocket

`GET /ws?token=<JWT>`

Браузер передаёт JWT в параметре `token`, потому что браузерный WebSocket API
не позволяет задать заголовок `Authorization`. Сервер проверяет подпись и срок
действия JWT до подключения. При прямом подключении из другого клиента можно
передать `Authorization: Bearer <token>`.

Отправляемый кадр:

```json
{"text":"Привет"}
```

Сервер сохраняет сообщение и затем рассылает его участникам комнаты.
Сообщение останавливается при пустом тексте или длине больше 2000 символов.

## Проверки

```sh
gofmt -w *.go
go test ./...
go vet ./...
go build .
```

`go test` не требует подключения к MongoDB. Для полной проверки регистрации,
входа и обмена сообщениями нужна доступная база MongoDB.
